# Architecture

```
WinUI 3 window (detachable)
  ├─ Sidebar session → tabs → recursive split panes
  ├─ TerminalView: TextBox input + event-driven native D3D12 composition visual
  └─ RemoteTerminalSession: cached cells/images and input IPC
       │ current-user named pipe
toiqtty.SessionHost.exe (independent lifetime)
  └─ Pane ID → TerminalSession
       ├─ ConPtyProcess: child process, input queue, output reader
       └─ GhosttyTerminal: terminal state, scrollback and graphics
            └─ toiqtty-native.dll → ghostty-vt.dll
```

## Terminal ownership

The application uses referenced `Toiqtty.Core` and `Toiqtty.Client` assemblies. Core owns the terminal engine, platform adapters, layout/settings models, Lua evaluation, wire contracts and snapshot codec. Client owns frontend IPC, ordered input, metadata scheduling, browser-cookie services and asynchronous session persistence/lifecycle coordination. The host references Core and contains its own server implementation; WinUI references Client. Tests reference these same projects rather than recompiling application sources. Published validation replaces the fixture's shared/native DLLs with the exact release files before running core checks. Namespace names are unchanged. The session-host wire is protocol 3; see the IPC paragraph below.

`TerminalGridGeometry` publishes the displayed cell sizes, native cell sizes, dimensions and display scale together when the matching frame is accepted. Measurement can prepare a pending geometry while the previous grid remains displayed. Native selection and mouse positions derive from cell fractions in this geometry rather than independently multiplying by the current display scale. Remote capture validates physical cell dimensions as well as rows and columns; a stale frame cannot apply unread-frame backpressure. Pointer presses wait for a pending geometry transition rather than starting a gesture against a different grid. Accessibility screen-point conversion uses the same geometry. Automated geometry/gesture checks are distinct from real Windows pointer injection.

`PaneNode.Remove` edits the layout without disposing a shell. `SessionLifetimeCoordinator` owns explicit close completions, while remote `CloseAsync` and `DetachAsync` have distinct meanings and idempotent completion. Window close drains admitted input, queued layout persistence, explicit closures and remote detach before releasing the window. `SessionPersistenceQueue` captures detached layout snapshots on the UI thread and serializes writes in the background. Pending saves coalesce; navigation cannot downgrade a pending structural save. Failed writes remain observable and do not strand future saves. Search, clipboard retrieval and drag/drop negotiation have asynchronous session operations. `SessionHostClient` has no synchronous host call: connecting, creating, saving, detaching and shutting down are all awaited (see below). The core architecture checks scan the `Toiqtty.Client` sources and the non-`Diagnostics` WinUI sources and fail on `GetAwaiter().GetResult()`, any `.Wait(` and a `.Result` whose line neither awaits it nor tests `IsCompleted`. Diagnostics drivers block only through `HostCheckCalls`, and tests only through `HostTestCalls`. Preference-file writes are still a small local synchronous write and remain a candidate for a later measured change.

The host's layout transaction semaphore preserves persistence order separately from its session registry lock. Layout `sync` and shell `create` requests carry a per-frontend epoch and a revision stamped when each is sent, in the serial persistence worker or a session's create gate; a `sync` never removes a shell that the same frontend created after that sync. Shell creation never blocks the window: `RemoteTerminalSession.Start` returns a placeholder session at once, and entry 0 of its ordered input queue awaits the single-flight host connection, then a structural layout save that names the pane (shared by every shell requested in one dispatcher turn; skipped for panes restored from a live host's layout, which are already durable), then sends `create` (without a layout) through a four-way client admission. Input queued meanwhile follows the create in order; closing first spawns nothing; a failed create faults `Ready`, answers queued input with its code, and the window swaps in a Retry panel. A host error reply is distinct from a transport failure: rejected input leaves the ordered input channel open, while an ambiguous transport failure still closes it without replay. The host accept loop releases a connection slot only after its pipe instance closes, and transport failures retry rather than ending owned shells. File creation, flush and replacement run outside the registry lock; shell creation and capture-gated disposal also avoid holding that registry lock. Ping returns a detached layout snapshot. Diagnostics live under the WinUI `Diagnostics` directory, and `WindowDiagnosticOptions` owns startup-mode parsing and fixture preparation for both application composition and the window. The integration drivers compile only when `ToiqttyDiagnostics` is true, the default for development and test builds. `scripts/publish.ps1` ships releases without them; `-Diagnostics` publishes the same binary with the drivers for GPU, endurance, performance-regression and published UI suites. Product builds keep mode parsing, which rejects validation flags with an explicit error, and the startup probe, so startup is measured on the shipped binary. The drivers still share private fields with the window through partial classes.

Every sidebar session contains tabs, each with an independent recursive `PaneNode` tree. Each leaf references one host-owned terminal. Splitting preserves the existing shell in one child and creates a new shell for the other. Closing a pane closes that shell; closing a tab or sidebar session closes its descendant shells. views are cached by stable pane identity and rebound to the same shell through tab/session switches, splits, moves and zoom. Hidden views suspend input, capture and drawing while retaining their swapchain, text layers and image textures. A least-recently-used cache retains at most eight hidden views and an estimated 128 MiB of hidden GPU resources; visible views are excluded. Eviction disposes presentation resources without ending the host-owned shell.

Each terminal view reserves a fixed-width gutter for a native WinUI scrollbar. `ghostty_terminal_get(SCROLLBAR)` supplies total rows, offset and visible length during snapshot capture; `SCROLL_VIEWPORT_ROW` positions the viewport for thumb and accessibility actions. These use upstream Ghostty state, including alternate-screen and retention behavior. An optional `Scrollbar` reply field accompanies the existing binary frame and leaves the native frame ABI unchanged. Thumb updates are coalesced to the render cadence. Middle-button autoscroll is a presentation gesture that routes nonzero movement through Ghostty's existing wheel encoder when an application requests mouse input, falling back to relative terminal-history scrolling otherwise. Zero retains its existing jump-to-bottom meaning and is never emitted by stationary autoscroll. Wheel reports use the anchor's position and omit the Shift modifier used to start a forced gesture. Ordinary middle clicks still go to mouse-reporting apps; Shift starts autoscroll, and Shift+wheel retains the direct terminal-history override.

`MainWindow.TabLayouts` also retains complete attached split-tree roots. Switching hides the previous root and resumes the next root's controls without unload/load cycles. A tree signature includes pane identity/kind, orientation, ratios and zoom; structural changes invalidate only the affected roots. Wrappers release their children before root removal so moved controls can be reparented safely. Hidden roots are independently bounded, including browser-only tabs. Tab ListView items survive selection changes; only the previous and current selection styles change.

The host's `navigate` operation accepts a coalesced selection/focus-only request. Immutable snapshots are created on the UI thread and sent by a background worker after a 20 ms coalescing window. A shared gate serializes this work with structural saves; structural saves supersede pending navigation. The host applies only IDs that still exist, refreshes owned shell directories, and cannot create, move or delete shells through this request.

`SessionLayout` permits pane moves only within the owning sidebar session. Other sessions and new-session destinations are rejected before mutation, including drag previews. A move extracts a leaf without disposal, collapses its old split and inserts the same leaf into another split or tab in that session. Empty source tabs are removed in the same edit; the session remains. The host receives one complete saved layout with all retained pane IDs. Terminal session objects and cached WebViews survive relocation. Attention and notification activation resolve the pane owner. Sessions and tabs both use WinUI's native ListView reordering, with horizontal ItemsStackPanel layout for tabs. Tab labels contain no nested selection button to capture the drag gesture. Context menu order actions provide keyboard access. Drag completion restores pane input focus. Hovering and cancelled drags do not change the saved order.

The host starts on demand and holds a per-data-directory exclusive lease. It exits after the last shell is closed or exits naturally, with a short grace period to deliver final output. Closing or crashing WinUI leaves the independent host and its ConPTY handles alive. Reopening discovers the existing host and reattaches pane IDs; existing processes are never recreated during attach. All restored panes reattach through one batched `attach` request sent off the UI thread, selected tab first, with each distinct settings graph sent once; each pane's input-queue gate takes its state from that reply, and a pane the host no longer has falls back to its own create. Reboot or host failure ends these local processes. Cold startup runs configured Lua startup actions or creates one default shell; it never reconstructs the previous session/tab/pane layout from disk. A deliberate Stop sessions and quit command is separate from closing the window.

Shell exit observation uses a registered wait on the original process handle rather than blocking a thread-pool worker for each live shell. A SafeHandle reference keeps that handle alive through concurrent disposal; the wait wrapper never owns or closes the original handle. Exit codes come from the signaled process, and teardown unregisters the wait and releases the reference. A constrained-worker regression checks queued work with eight live shells, natural exit codes, output draining and concurrent explicit closure.

The host, control and instance pipes have data-folder-derived names, so servers create their first instance with `FirstPipeInstance` and the host exits rather than share a name another process owns. Clients reject a pipe server running below their own integrity level, caching verified server process IDs. ConPTY input/output use separate current-user-only, randomly named pipe pairs. Parent ends use overlapped I/O completion, while ConPTY receives synchronous client handles. First-instance creation prevents reuse of an existing pipe name, and initial connection waits are bounded. Pending reads and writes therefore leave workers available rather than implementing ReadAsync on synchronous anonymous-pipe FileStreams. The ordered input channel and output-draining teardown remain intact. The constrained-worker test includes eight pending output reads, and confirms that unrelated queued work still runs with a four-worker limit.

IPC uses versioned, length-bounded messages over a current-user-only named pipe, and pins each client to a host-instance ID. Protocol 3 keeps one flat, source-generated request/reply envelope; each operation carries its own typed payload and typed result instead of positional numbers, and every error reply carries a string `ErrorCode`. The operations are `ping`, `create` (optional initial columns/rows; `Created` is false when the pane already existed), `attach` (deduplicated settings plus up to 256 panes), `close`, `detach`, `shutdown`, `sync`, `navigate` and `settings`; pane input `key`, `copy-or-key`, `send-text`, `paste`, `paste-checked`, `clipboard`, `mouse`, `gesture`, `scroll`, `scroll-to`, `select`, `focus` and `resize`; reads `capture`, `watch`, `states`, `find`, `copy` and `hyperlink`; and drag/drop `drop` and `drop-async`. Error codes are `ProtocolMismatch`, `HostChanged`, `InvalidRequest`, `UnknownOperation`, `SessionMissing`, `SessionExited`, `InputBusy`, `LimitExceeded`, `RequestTooLarge`, `ReplyTooLarge`, `ShellStartFailed`, `ConsoleFailed`, `TerminalFailed`, `StorageFailed`, `Timeout`, `ShuttingDown` and `Internal`, plus the client-only `Disconnected`; an unknown code from a newer peer reads as `Internal`. The client raises them as `SessionHostException`s, all still `IOException`s: `HostRejectedException` when the host answered (the input channel stays open), `HostTransportException` for EOF, timeout, connect failure or a changed host (the channel fails), and `SessionHostVersionException`. Key, paste and mouse input to an exited pane or a full ConPTY queue still produce a status notice rather than an error reply. Framing, the pipe name and the 16 MiB JSON / 96 MiB snapshot limits are unchanged from protocol 2, `Protocol`, `Operation` and `Error` keep their protocol-2 types, and no protocol-3 field reuses a protocol-2 name with another JSON type; `HostV2Wire` fixtures check both directions. A running protocol-2 host is never reused or upgraded in place: the frontend opens its upgrade window, and those sessions must be stopped from the older version before the new one starts its host. Every pane's requests go through one `OrderedHostInput` queue: entry 0 is the open gate (connection, layout commit, then `create` or the `attach` result), later entries are sent strictly in admission order, and its held-key and focus reserves recognise `key` and `copy-or-key`. The host checks the protocol version and host identity before decoding any payload, so a peer of another version always gets a framed mismatch reply rather than a closed pipe. Replies always write `Protocol`, `Host`, `ProcessId` and `Error`; every other field is omitted when absent and reads as the default protocol 2 also declared, so a status-only capture or an idle watch reply carries only the envelope and its own fields. A completed watch names its woken panes only as the keys of `OutputRevisions`. Ctrl+C is one `copy-or-key` request that copies a selection or sends the key under one parser-gate acquisition. Input is never replayed automatically after an ambiguous failure. Input the client refuses itself is coded the same way: `InputBusy` for a full queue, `ShuttingDown` once the session is closing, and the transport code (`Disconnected`, `Timeout`, `HostChanged`) for everything after a failed delivery. Cells, full graphemes, style/cursor state and graphic placements cross losslessly; image pixels transfer once per cached generation. Visible windows poll asynchronously and render cached snapshots without pipe I/O inside Draw. Tracked views retain a read revision beside their destination buffer. Per-row cache revisions accumulate skipped captures; only newer rows are copied. Replacing a view buffer resets its read revision. Untracked readers still compare their destination cells. Hidden terminals still drain output, update directories and advance upstream animation/hold clocks. Per-terminal frame revisions expose maintenance captures on reattach. The regular UI-smoke and hardware guide use local terminals to keep their original isolated teardown behavior; dedicated persistence probes exercise the host path.

The first attached view and admitted input wake a coalesced semaphore wait in the remote capture loop. Under protocol 3, one `watch` connection per client waits on a revisioned output pulse, then wakes only the affected visible panes. One unread frame applies backpressure until the view copies its cells; consuming it wakes the next capture immediately. Input acknowledgements can supersede a waiting frame, and snapshots with obsolete viewport dimensions cannot apply backpressure. There is no fixed inter-capture sleep. Animation/hold deadlines and a one-second watchdog remain; hidden panes retain a 400 ms metadata cadence. If the watch fails five times in a row the client marks it degraded and falls back to 8 ms polling during recent input and 16 ms otherwise. A newly cached frame posts one coalesced dispatcher invalidation rather than waiting for the UI's 33 ms maintenance timer. That timer still owns blink, resizing and autoscroll. Native tab reordering defers refreshes until the drag completes and commits the resulting item order before restoring terminal focus.

TerminalCanvasSurface presents opaque, full-opacity content through a native two-buffer Direct3D 12 composition swapchain attached to a WinUI CompositionSurfaceBrush/SpriteVisual. The swapchain is created from the direct command queue, uses the current backbuffer index, and transitions each buffer to PRESENT before presentation. Translucent/faded panes copy the completed texture into a premultiplied CompositionDrawingSurface through the 11-on-12 bridge; this retains WinUI opacity and system-backdrop behavior.

`native/renderer.cpp` records native D3D12 graphics command lists and owns root signatures, blend/sampling pipeline states, descriptor heaps, explicit texture barriers, and upload buffers. Shaders compile as shader model5 during the native build. `native/renderer-dx12.h` manages a bounded adapter-LUID device/direct-queue cache shared by renderers on the same DX12 adapter, along with a shared fence and the Direct2D/11-on-12 bridge. Each renderer has three allocator/list slots. A slot resets only after its submission fence completes; upload bytes are immutable while executing. Upload storage is bounded to four MiB per slot, twelve MiB per renderer. Descriptor heaps, resources and texture-accounting leases remain retained until the associated GPU work completes. Completed references retire during slot reuse or accounting reads. The process cache retains at most eight adapters (normally hardware plus WARP), evicts unused entries at its limit, and recreates removed devices. It holds no original Win2D providers. MainWindow drains the cache after disposing views and before COM teardown; the DLL does not run GPU waits during process detach. Device teardown drains submitted work. Logical resizes inside retained capacity reuse the buffers without a GPU-idle wait. Growth rounds allocation to 128-pixel buckets; falling below half the allocated width or height releases the old peak. Hard resizes drain and release every old buffer before ResizeBuffers. DXGI keeps the allocated source size while WinUI crops the logical region; shrinking both would apply scaling twice. Native HRESULT failures propagate through the existing surface recovery path. Unsupported hardware selects the shared WARP provider. There is no separate render thread; XAML owns recording and the GPU executes queued work asynchronously.

The renderer records each pane's background/text row targets and final composition in one frame scope. Switching drawing sessions flushes vertices without submitting the list; Present submits the completed frame. Atlas interop, upload capacity rollover and diagnostic readbacks remain explicit submission boundaries. Standalone targets still submit immediately, preserving cross-renderer producer/consumer ordering. Allocator state caches reset with the command list. Unchanged resize, DPI matrix and composition-attachment calls are skipped.

The renderer groups renderer memory by lifetime. Device scope owns immutable root signatures and pipeline states, created once per shared adapter device. Pane scope owns the renderer, swapchain, upload slots and `DirectXPresentation`; its visual, brush, opaque swapchain surface and premultiplied drawing surface are reused across alpha/opacity/DPI changes. The DXGI chain keeps a premultiplied format throughout its lifetime; opaque frames contain alpha=1. Cached translucent storage remains included in hidden-view accounting even when the pane returns to opaque presentation. Disposal detaches the visual and releases presentation before the native renderer. WinUI projections and driver allocations retain their platform ownership rules; this is not a process-wide arena or a replacement for managed GC.

The capture path separates the 40-byte managed cell from the unchanged native inline UTF-8 ABI. Managed snapshots own decoded strings, with shared ASCII strings and complete long graphemes. Snapshot replies write into one exact-sized, reply-owned byte array that survives through the asynchronous pipe write. The serialized frontend decoder repairs only the rows separating its current and spare buffers before applying a delta; a full frame or rejected decode invalidates that repair history. The published baseline is never decoded in place. Failed decodes return newly rented arrays and leave caller-owned spares with their caller. Focus assignments and pane background brushes avoid redundant XAML updates; inactive transparency surfaces retain their actual size until selected again.

The capture path keeps host capture text in UTF-8 through snapshot encoding. The private native transfer cell is 64 bytes, including 32 inline text bytes; byte-sized underline variants (0–5) and cell widths (0–2) leave flags and colors at 32 bits. Its size, inline offset and capacity are validated against the loaded bridge before capture. Larger graphemes use independent row arenas. A dirty row resets its arena, grows using offsets, and binds pointers only after growth ends; unchanged rows retain their bytes. Resize releases all row arenas and unusually large peaks shrink after replacement. Host capture copies overflow bytes while holding the parser gate, clears borrowed pointers, and retains its owned capture buffer under a separate per-pane capture gate until encoding finishes. Frontend cells still own decoded strings for Windows text and accessibility APIs.

Snapshots may use style runs, independently of row deltas; protocol 3 has no capability negotiation, so every host offers them. A run contains one style followed by lossless per-cell UTF-8 text lengths; it cannot cross a row. The encoder keeps the per-cell representation when it is smaller. Reusable read connections (`ReuseReadConnection`) allow eight exclusive capture channels per client, shared through remote-session leases. The last lease drains and retires them. The host limits persistent read channels to sixteen of its thirty-two accepted connections, leaving room for input and control. Only stale read-only requests can reconnect once; input and control are never automatically replayed. JSON frames own their header and payload through the asynchronous write, use source-generated contracts, and rent common buffers only up to 64 KiB; larger buffers have call lifetime. The actual JSON wire limit remains 16 MiB.

Status revisions omit an unchanged immutable status/history snapshot from capture replies. The remote owns this baseline independently of input acknowledgements and hidden-pane metadata. A missing baseline forces a full recovery capture. The output watcher retains visible pane interests through temporary capture/backpressure pauses. It still sleeps when no pane currently needs capture. Notifications reach visible owners even during a capture, which preserves output arriving after an empty capture began; generic demand-only subscribers retain their unacknowledged catch-up revision.

Each submission has a reusable CPU arena for a deduplicated resource-pin set and a separately bounded GPU upload arena. Repeated draws pin each texture once per submission. A texture's intrusive lifetime includes its native resource, descriptor leases, wrapped interop textures and accounting owner; active targets and pending batches hold independent leases. Descriptor leases are move-only values, without a separate shared allocation per slot. Completed fences release the pin set before its CPU pages or upload bytes are reused. Retained 16 KiB bookkeeping pages shed a previous oversized peak after usage falls. Destruction also releases the command list before abandoning its recorded pins after GPU idle. Shaped glyph arrays use one packed allocation per run in an entry-owned monotonic arena; eviction destroys font references and releases the whole entry arena. The 8 MiB shape budget counts actual arena blocks including growth slack.

SRV and RTV descriptors use shared device pages of 1024 slots. Recorded commands retain their texture owners, so disposing an image cannot recycle its slot before the command's fence completes. Free-list release is synchronized for SafeHandle finalizers. Unused overflow pages retire during stats collection, with one reusable page retained per heap type. Shader-visible heaps stay bound while draws use the same page; root/pipeline/target state changes are recorded only when necessary.

`scripts/test-native-lifetimes.ps1` checks arena alignment, stable addresses, peak shedding, deduplication and retirement without launching a window. `scripts/test-native-gpu-lifetimes.ps1` exercises the real renderer on hardware and WARP with native DirectWrite/Direct2D provider fixtures, GPU pixel readbacks, disposal before flush, upload rollover, shape retirement and stable swapchain identity. Both accept `-AddressSanitizer`. The GPU fixture links the instrumented renderer into its executable and loads no XAML composition engine. Whole-WinUI sanitizer attempts failed inside platform/runtime code, including a CLR out-of-memory failure; those are failed validation paths, not clean sanitizer results. Standalone instrumented native GPU and capture fixtures provide the sanitizer evidence. `scripts/build-renderer.ps1 -AddressSanitizer -OutputDirectory <isolated-test-directory>` can instrument a separate native DLL for further investigation. Sanitizer DLLs are test artifacts and must not enter release output. `otr_lifetime_stats` reports pin requests/unique/live pins, arena and upload bytes, shape arena bytes, descriptor pages and pipeline initialization count. The WinUI GPU suite additionally exercises descriptor page reuse and rejects more than two composition surfaces per renderer during stress. `test-directx.ps1 -TrackHandles` optionally samples handle types with a locally supplied Microsoft Sysinternals Handle binary; diagnostic sampling is not a performance comparison.

D3D12 draws backgrounds, dirty row layers, glyph quads, decorations, Powerline shapes, cursors, wallpapers and Kitty image placements. Font configurations own native DirectWrite formats and fallback settings. Eligible primary-face ASCII uses pinned HarfBuzz; Unicode, color, italic, missing-glyph and explicit-kerning runs retain DirectWrite shaping. Win2D supplies font configuration, measurements and reference fixtures. Direct2D rasterizes glyph masks/color/italic runs through a dedicated 11-on-12 context. Atlas textures are checked out with UnwrapUnderlyingResource for native DX12 sampling and returned with fence dependencies before rasterization. Unwrap's pending transitions are flushed before subsequent native queue commands. Native texture copies and all terminal triangles remain on DX12. The diagnostic test accepts -Offscreen, hiding only its isolated window and explicitly marking desktop pixel checks skipped; GPU readback/state/lifetime tests still run. A minimized visible test remains a failure, not an automatic skip. The original Win2D device does not execute terminal drawing. CanvasRenderTarget reference/readback fixtures use an explicitly diagnostic CPU staging copy between the original provider and the DX12 texture; production row layers, images and swapchain rendering do not use that path.

Eligible ASCII style runs of eight or more cells use a 4096-byte view-owned scratch buffer and a font-owned HarfBuzz buffer. Preparation and drawing consume it synchronously, so no borrowed glyph pointer survives into a GPU command. Short repeated runs retain the bounded shape cache; a fixed 128-entry directional ASCII key table avoids repeated tiny strings. Unsupported runs preserve the complete DirectWrite context instead of fragmenting it around ASCII cells. HarfBuzz is built from checksum-pinned source using its DirectWrite adapter, with its licenses shipped alongside the renderer.

The native DirectWrite collector can copy the first analysis into a cache-entry arena and adjust cluster advances to the terminal grid. The borrowed cell-width map exists only during that synchronous collection. Backing IDWriteTextLayout spacing is still updated, so fallback and reconstruction after cache eviction remain correct. Italic, explicit kerning, nonmonotonic RTL and unsupported clusters keep the established analysis path. On systems exposing ID2D1DeviceContext7, integral-pixel color glyphs cache system-rendered COLR/bitmap/SVG content in the existing atlas; fractional grids retain whole-layout rasterization. Older systems use the existing layout path. These are bounded special cases within the existing renderer, not additional rendering backends.

Whole-layout fallback rasterizes into one pane-owned scratch target before copying to the atlas. That fixed origin prevents fractional-DPI coverage from depending on atlas packing. Oversized strips preserve the physical origin's fractional phase while placing destination quads on integer physical pixels. Submission pins and interop fences protect the scratch copy before the next raster write.

| Lifetime | Owned memory | Release/reuse boundary |
| --- | --- | --- |
| Shared adapter device | Root signature, pipelines, descriptor pages | Last device user; unused overflow descriptor pages retire |
| Pane | Swapchain capacity, raster scratch, three upload/list slots | View eviction/disposal; large resize peaks shrink |
| Font configuration | DirectWrite format, HarfBuzz font/buffer, cluster scratch | Font/configuration reset or view disposal |
| Shape/layout cache entry | Packed glyph arrays, font references, arena | Bounded eviction or layout retirement |
| GPU submission | Upload bytes, deduplicated texture/resource pins | Its completed fence |
| Host capture | Native row arenas and separately owned UTF-8 overflow | Dirty-row replacement, resize, or pane disposal |
| IPC frame | Header and encoded payload | Awaited pipe write completion |

Atlas pages start at 1024 square, grow only as needed, and retain at most two 2048-square pages / 2048 entries. The native shaped-run cache is bounded to 8 MiB / 2048 entries. Managed layouts remain capped at 2048 and block-cursor layouts at 256. DirectWrite cluster widths, fallback, ligatures, visual order and primary-font baseline are preserved. Unicode/color/italic/combining pixels are compared against the DirectWrite reference at five DPIs; existing grayscale contrast tolerance remains 12/255. Layout retirement releases native owners while reusable glyph masks survive. Wallpapers can share textures across renderers on the same DX12 device. Cross-device texture use is rejected. Hidden-view accounting includes native textures, allocator upload storage, both swapchain buffers and translucent composition storage; existing eight-view / 128 MiB eviction limits remain.

Opaque bulk invalidations use one coalesced low-priority dispatcher callback gated by DXGI readiness. The optional `frame_pacing` setting (off by default) instead admits output-driven redraws on the compositor tick, at most once per display refresh; input-driven redraws are never paced. It roughly halves UI CPU during heavy output without changing input latency. After a pane presents, each new ASCII-capable font rasterizes its printable glyphs into the atlas in one interop transfer per page at low priority, so the first keystrokes in a new pane need no per-glyph rasterization. Glyph positions snap to the 1/64-pixel phase grid before splitting into pixel and phase, so floating-point drift cannot create duplicate atlas entries. Input promotes a queued bulk callback to normal priority. Transparent panes retain the composition callback because their drawing surface follows the compositor. DXGI readiness uses a duplicated caller-owned event and a registered wait, without reserving a worker thread. Disposal, suspension and stale callback generations cannot revive a view. Present(DO_NOT_WAIT) preserves a nonblocking admission path; a one-second watchdog handles missed notifications. Accepted Present/EndDraw drives presentation diagnostics. Explicit fences protect allocator/resource reuse and readbacks. These counters measure CPU submission completion, not physical scanout. Device-loss callbacks, WARP replacement and owned adapter transitions are distinct from a physical driver TDR.

The D3D12 debug collector preserves cumulative raw error/warning counts and a bounded text tail, drains the SDK queue before it fills, and treats dropped SDK messages as a validation failure. Three performance-only IDs are separately classified as interop notices: 1328 (legacy buffer initial state, including the compatibility upload convention), 680 (depthless internal raster PSO), 820 (temporary raster target fast-clear value). All raw warnings remain visible; no error is exempted, including those IDs at error severity. Validation requires zero errors and zero warnings outside those three IDs. Reports must say zero unexpected warnings, not zero raw warnings.

`scripts/test-directx.ps1` compares glyphs, images, cropping, clips, blend modes and Powerline pixels; it also tests native DX12 target/descriptor disposal, multi-page descriptor reuse, frame batching and producer/consumer queue sharing. Stress tests read actual swapchain pixels across DPI/alpha/size changes, hardware/WARP transitions and onscreen marker checks. Offscreen/readback results do not establish physical scanout performance. Renderer throughput, input latency and process memory need separate matched measurements; adopting DX12 alone does not establish a speedup. The host transport, libghostty terminal protocols and accepted-frame selection/IME/accessibility geometry are unchanged.

`scripts/test-performance.ps1 -RenderProfile` enables opt-in QPC timers and writes `performance-render-profile.json` beside the normal benchmark report. Snapshots include per-renderer list/reset/wait counters, elapsed allocator/submission/raster/presentation time, upload bytes, and process-private-memory checkpoints during device initialization. DevicePipelineTicks measures actual root-signature/PSO creation, rather than the former renderer-context initialization interval. Pipeline timing, device memory checkpoints and descriptor-page counts are shared device values, not values to sum across panes. Timings overlap (reset includes fence waits, Present includes submission); they are CPU-side elapsed intervals, not GPU execution time. Normal comparisons run without this switch. `-Translucent` seeds an isolated 72% alpha setting to exercise CompositionDrawingSurface on old and new releases. The fixture disables Lua/system-backdrop initialization, so this measures the terminal alpha-copy route rather than the cost of the Mica backdrop.

Frame acquisition and input continue to share accepted grid geometry. Parser-published status and mouse modes are immutable snapshots updated before output version publication, so UI reads avoid waiting on a busy parser gate. Incremental snapshots carry row/image generations; a frontend retains its last valid frame on contention and retries rather than displaying mismatched geometry. Native cell dimensions, columns/rows and rendering DPI are accepted together. Canvas-local pointer positions, IME placement and accessibility points derive from that accepted geometry. A new font or padding measurement remains pending until the corresponding frame can be displayed.

Each view retains its original session reference through pane-model edits. Suspension detaches visible capture and queued rendering; disposal releases presentation state and listeners without inferring shell ownership from the edited model. Frame callbacks use the captured UI dispatcher and recheck suspension/disposal. Window close detaches rather than terminating the host; explicit shell closure follows the separate lifecycle coordinator. Hidden-view eviction never ends a host-owned shell.

Primary API references: [D3D12 swapchains](https://learn.microsoft.com/en-us/windows/win32/direct3d12/swap-chains), [11-on-12 resource checkout](https://learn.microsoft.com/en-us/windows/win32/api/d3d11on12/nf-d3d11on12-id3d11on12device2-unwrapunderlyingresource), and [fence-based resource return](https://learn.microsoft.com/en-us/windows/win32/api/d3d11on12/nf-d3d11on12-id3d11on12device2-returnunderlyingresource).

## Ghostty boundary

`TerminalClusterMetrics` unwraps a Win2D text layout through `ICanvasResourceWrapperNative` and reads `IDWriteTextLayout.GetClusterMetrics` into renderer-owned storage. Both COM references are released in `finally`. Retained capacity is capped at 8,192 clusters; larger runs use transient storage without truncating text. Character counts and widths feed the existing cell-spacing algorithm. Exact-pixel comparisons against the WinRT projection cover styles, ligatures, fallback, RTL and combining text; this optimization does not replace DirectWrite shaping or Ghostty grapheme state.

`native/toiqtty.c` consumes Ghostty’s public `include/ghostty/vt.h`, not `ghostty.h`. Ghostty owns the terminal parser, state, scrollback, resizing, input encoding, search, and selection formatting. The bridge owns the C handles and produces a cell ABI for managed code. A frame is read in one native call rather than making thousands of P/Invoke calls for individual cells.

The cell ABI has foreground/background ARGB, style/selection flags, and a 32-byte inline UTF-8 grapheme buffer. Larger engine graphemes use row-owned native overflow storage, copied under the parser gate before the capture escapes. The renderer draws backgrounds before glyphs so a wide glyph cannot be erased by its continuation cell. DirectWrite shapes contiguous style runs, adjusts cluster advances to Ghostty cell widths and uses system font fallback with a stable primary-font baseline. A left-to-right override preserves the cell order already assigned by Ghostty. Layout caches are bounded; invalidating font settings disposes them. Changed rows repaint retained text/background layers; images and the cursor composite independently.

Character-spacing batches combine only adjacent single-character clusters with exactly equal spacing adjustments; multi-character clusters retain individual updates. Width keys encode unusual grapheme advances compactly and omit the map for ordinary one-cell text. A FIFO limit evicts one of at most 2,048 layouts at a time instead of clearing the entire cache on a miss. Empty trailing cells without decorations do not need text shaping. Reusable row flags replace per-frame hash sets. Overnight GPU checks can invoke the same Render method into a retained offscreen target, keeping cache and pixel checks meaningful when Windows stops presenting an occluded or display-off window; that mode does not measure onscreen presentation latency or a real driver TDR.

The bridge also exports underline style/color, cell width, cursor color/blink, and an image placement snapshot. Kitty transmission, decoding requests, placement, scrolling, deletion, compression, and animation state remain owned by Ghostty. Windows WIC implements the PNG decoder callback. A 64 MiB image storage limit applies per screen; renderer snapshots and GPU textures add memory beyond that limit. Snapshot pixels are copied while holding the session lock and cached by Ghostty's process-wide generation stamps, preventing stale pointers and same-size retransmission errors. The renderer clips to the grid and draws the three Kitty z-layers around backgrounds and text.

The pinned C API lacks host entry points for animation ticks and resolved Unicode-placeholder fragments. `native/patches/graphics-host.patch` adds two narrow exports that call Ghostty's existing implementations, and resolves relative placements rooted at virtual parents using the same rule as Ghostty's renderer. The build applies this patch idempotently and fails if it no longer applies. These are toiqtty extensions, not unmodified upstream API guarantees.

Synchronized output (mode 2026) captures text and graphics at the hold-begin callback, including when a whole frame arrives in one write. The renderer keeps that snapshot until release, resize, user scrolling, or a one-second timeout. Animation redraws are scheduled independently of new shell output. See [PROTOCOLS.md](PROTOCOLS.md) for tested coverage and remaining compatibility work.

JetBrainsMono Nerd Font Mono is bundled in six faces under `Assets/Fonts`, with upstream version and SHA-256 hashes in `source.json`. The renderer loads each face directly through a `file:` URI, which works in the unpackaged application without installing fonts. Filled Powerline separators use analytic native GPU shapes with antialiased sloped/curved edges and opaque flat joins. Cell dimensions are rounded to physical pixels, and backgrounds use aliased fills, avoiding antialiased seams at fractional DPI. Version 1 session files using the original Cascadia Mono default migrate to this font once; later versions preserve subsequent user choices. Version 4 migrates the old default shell in both settings and restored panes to PowerShell 7 when available, retaining custom commands.

The public Ghostty API is evolving, so the source and Zig compiler are pinned. A dependency update must rebuild the bridge and pass integration checks. No native ABI enum values are guessed in C#: the bridge uses upstream headers at compile time.

## ConPTY and threading

The output reader forwards bytes unchanged to Ghostty under a per-session lock. Rendering, resizing, search, and input encoding use the same lock. Rendering uses TryEnter and keeps its last snapshot on contention, retrying on the next tick. Incremental capture consumes Ghostty row dirtiness. UTF-8 decoding occurs inside Ghostty, preserving multibyte characters split across reads.

Each child receives a Unicode environment block with `TERM=xterm-256color`, `COLORTERM=truecolor`, and toiqtty's terminal identity, rather than the launcher's terminal capabilities. Other inherited variables, including an explicit `NO_COLOR` preference, are preserved. PowerShell reads these capabilities before loading profiles.

The application ships Microsoft's pinned ConPTY redistributable (`conpty.dll` and adjacent `OpenConsole.exe`) instead of relying on the OS console host, which can strip graphics APC sequences. Both application and integration tests use it. Grapheme-width mode aligns the console host's width measurement with Ghostty. Size callbacks answer XTWINOPS and mode 2048 queries using the physical cell dimensions; XTVERSION and device attributes identify toiqtty and advertise only the supported features.

Terminal-generated replies and user input enter a separate ordered writer queue capped at 256 entries and 8 MiB including in-flight data. Paste framing and content are admitted as one transaction. Admission is atomic; rejected user input produces an activity warning. Writing never blocks the UI or the output reader, avoiding pipe backpressure deadlocks. Child startup explicitly sets `STARTF_USESTDHANDLES` with cleared handles so a launcher’s redirected standard streams do not bypass ConPTY.

Process waiting holds a safe handle reference. Child exit initiates pseudoconsole closure so its output handle is released and the reader can see EOF. Explicit pane closure terminates the owned child and closes ConPTY on a background task; the output reader continues draining until the pipe breaks. This handles closure during process startup as well as normal shell exit. An explicit close discards pending input.

## State and configuration

Startup probes separate terminal overhead from shell initialization: `scripts/test-startup.ps1 -AppDirectory <release> -UserConfig -ImmediateShell` uses a profile-free CMD readiness marker, while the default and `-Profile` modes measure PowerShell. Every iteration creates a fresh isolated host and then reconnects to it; traces include process startup, activation, first frame, and rendered readiness. These are process-launch measurements with normal OS caches, not reboot-cold measurements. Benchmark copies preserve the installed application's notification identity and user data.

The launch overlaps Lua evaluation and graphics device preparation with window construction. `StartupLuaEvaluation` transfers its isolated worker to live hooks only when needed. `StartupGraphics` owns an unpublished native device until the window installs it on the UI thread; a late worker cannot repopulate the renderer cache after window shutdown. Browser-only startup releases preparation without publishing a terminal device. The host signals a per-launch readiness event once its first pipe exists, with bounded polling retained for older hosts and lease races. Generated configuration JSON preserves the existing wire and disk formats, shell fallback discovery is cached per process, and initial window sizing/appearance run once after configuration evaluation.

The application uses a window-owned, current-user-only public control pipe and the `toiq` CLI. CLI requests marshal to the UI dispatcher; layout mutations reuse the same session/tab/split methods as interactive actions. Literal input passes through the bounded ordered input queue. Rich bindings use a pure leader/key-table state machine, bounded ordered action runs, and isolated Lua callbacks returning validated action data. Visual settings invalidate shaping and accepted cell geometry; translucent backgrounds use premultiplied swap chains over Windows system backdrops. Fuzzy switching operates on existing session identities and cached metadata. No upstream terminal protocols were added.

The application uses a frontend-owned `--runtime-config` evaluator when presentation hooks are configured. Parsing retains Lua functions in that isolated worker; serialized settings contain only hook names. The window captures bounded, cached metadata and coalesces asynchronous requests, while the worker preserves Lua locals across calls. A 500 ms batch deadline and 256 MiB kill-on-close job bound failures. Worker exceptions or invalid output restore native formatting and leave the shell host intact. Failed reloads retain the previous worker; successful reloads replace it, and window close ends it. Tab hooks affect presentation only, never tab identity or persisted names. Status templates remain the fallback.

Global palettes are inherited by sessions without explicit themes. Custom schemes use upstream default-color setters, including extended palette entries; OSC and truecolor precedence remains in Ghostty. Cursor defaults use upstream default-style/blink options, preserving explicit application cursor choices. Font weight participates in render-cache/geometry invalidation, with genuine bundled Medium faces. Wallpapers are frontend-only, shared per window and composited below explicit cell backgrounds, text and terminal image layers. WIC decoding is asynchronous and bounded; texture caches retain at most two devices and recreate on replacement. Window-local wallpaper choices do not create, close or recreate shells.

`AppSettings.StatusBar` owns the optional bottom bar. It defaults to disabled; the collapsed control sits in an Auto-sized row so hidden chrome reserves no terminal space. Lua's `status_bar` table owns that complete settings object and is applied by the existing preference overlay and live reload. Bounded, validated left/right templates format current UI/cached terminal metadata without runtime Lua callbacks, process execution or synchronous IPC. Empty fields omit complete segments. Explicit colors override the active session palette; omitted colors inherit it. Runtime action messages use `SetStatusMessage`; actionable errors use the dismissible `StatusNotice` banner independently of bottom-bar visibility. The formatter never reparses substituted metadata as templates. Diagnostics check real row sizing, theme behavior, reload rejection and shell identity preservation.

Lua config is evaluated by an isolated `toiqtty.SessionHost.exe` worker, not by the host owning persistent shells. One-shot checks use `--evaluate-config`; windows retain a `--runtime-config` worker only when presentation hooks are configured. `LuaCSharp` 0.5.7 is pinned globally for the UI, host/helper, and integration runner. The managed Lua 5.2 interpreter exposes data-only toiqtty helpers, selected pure standard libraries, environment reads and local `require` modules. The worker waits for its request on stdin while the parent attaches a 256 MiB Windows job; bounded JSON travels over redirected pipes. A four-second deadline terminates stalled workers. Source/module count and bytes, result size, module paths, and startup layout bounds are checked. No filesystem-write, OS-execution, or CLR APIs are exposed to Lua.

The foreground window reads normal preferences from `preferences.json` (migrating the old saved-settings snapshot on first use) and overlays validated `toiqtty.lua` values. Effective settings remain in the host's layout snapshot; baseline preferences remain independent, so removing Lua fields restores UI choices. Applying settings retains the shared AppSettings object identity used by TerminalViews. UI controls disable Lua-owned properties, while unowned UI changes and font zoom are captured back into preferences only when they change. The optional `TOIQTTY_CONFIG` path overrides the app-data config path; working directories are never searched for scripts.

A debounced watcher observes Lua files/modules. Reload generations cancel superseded evaluations and wait for dialogs before replacing effective state. A failed evaluation leaves the current settings and startup plan intact and displays an InfoBar with inspectable details. Reload never runs startup creation. Valid startup session/tab/pane plans run only on a cold start according to when-empty or explicit replace-saved mode; live host attachment takes precedence. Manual command-palette creation clones the plan with fresh identities. Validation probes use isolated configs and data folders; ordinary terminal/browser/hardware probes disable user Lua loading.

Browser leaves extend the existing version-5 pane format with `Kind`, `BrowserUrl`, and `BrowserSourceId`; old layouts default to terminal leaves. They never allocate ConPTY sessions. The window caches and reparents WebViews by pane ID, preserving page state across tab/session switches and rebinding a leaf when a split clones its model. Closing a browser leaf disposes only that view. Browser pages stop with the window; reopening restores URLs and on-disk WebView2 profiles. A browser-only layout is saved directly once the shell host has exited.

IPC protocol 3 has no capability negotiation: a host of any other protocol version is treated as a different version. Startup checks compatibility before constructing the normal window or saving layouts. If an older host is live, a native WinUI upgrade window explains how to stop it through the installed version; live shells and saved state are not changed.

`BrowserRuntime` creates a WebView2 environment rooted at the app data directory's `BrowserData` subfolder. The independent toiqtty profile and each paired source have distinct stable profile names. The browser's chrome uses WinUI controls; HTTP(S) navigation is restricted to web URLs, popup requests become tabs, and terminal OSC 8 links can open embedded panes through a configurable setting.

`BrowserCookieBridge` is a bounded HTTP listener bound to IPv4 loopback. Every request carries an HMAC of its method, path, body and a fresh nonce under the connection token; the token itself never crosses the socket. Authenticated replies carry `X-Toiqtty-Proof`, an HMAC over the nonce, status and body, and the companion discards any reply without it, so a process that holds the port while toiqtty is closed receives neither the token nor cookies. Host must match the listener, and supplied Origins must be extension origins. Pairing uses a random 256-bit single-use token with a ten-minute deadline; each connection receives a separate persistent random token protected by current-user Windows DPAPI. Metadata is stored in `browser-connections.json`, separate from session layouts. Cookies remain in a bounded memory cache and WebView2's cookie store; they are never logged or written to configuration. Connections, origins, header/body size, concurrency, deadlines, and aggregate snapshot memory are bounded. UI work is coalesced to the latest snapshots.

The companion is packaged separately for Chromium MV3 service workers and Firefox MV3 background scripts. It requests the cookies API and optional site permissions through the browser, excludes private stores, and supports explicit Firefox container selection. Authenticated full snapshots update cookies and propagate deletion into that source's WebView2 profile. Browser-to-toiqtty sync is authoritative for configured sites and never writes back to the source browser. Partitioned cookies are counted and skipped because the current cookie-manager API cannot preserve their partition keys. Passwords, history, DOM storage and device-bound authentication keys are outside this bridge. Source browsers must remain open to sync; browser-owned data in toiqtty persists independently.

`SessionStore` validates bounded layout JSON and writes atomically via a unique, flushed temporary file. A window lease forwards subsequent launches to the existing foreground window; a separate host lease preserves shell ownership across window lifetimes. In normal operation the host writes saved state, including session/tab IDs, active tabs, recursive split ratios, shell commands, directories and focused pane IDs. Version 5 migrates each previous workspace into a session with one tab, preserving its existing splits and focus. Runtime terminal objects are excluded from JSON and reattached by pane ID. `SessionStartupPolicy` accepts this layout only when reconnecting to a host with owned panes. With no live host, it retains preferences and discards saved session identities and trees before Lua evaluation or shell creation. Legacy `RestoreWorkspaces`/`restore_sessions` values are accepted for compatibility and cannot enable replay; the restore-layout UI toggle is removed. Invalid/corrupt layouts fall back to a new session; missing directories fall back to the configured start directory.

The default location is `%LOCALAPPDATA%\toiqtty`. `TOIQTTY_DATA_DIR` supports isolated tests and development instances. JSON command strings are used as explicit local shell configuration; they are not obtained from terminal output. OSC directory updates affect metadata and restart directories. OSC clipboard requests use a synchronous Win32 MIME adapter with read/write policy, owned copies, bounded payloads and Ghostty paste grants. Program status, semantic command, progress and notification callbacks feed bounded session activity records.

Git branch polling runs outside the UI thread, passes literal arguments to Git, and uses a timeout. PowerShell integration wraps the existing host line reader and prompt, emits upstream-supported OSC 133 command boundaries/text/exit codes and OSC 7 directory metadata, and preserves PSReadLine callbacks, bindings and custom prompts. UTF-8 command metadata is capped at 600 bytes before percent encoding to fit upstream's fixed OSC 133 buffer; execution receives the original command. No profile files are modified, explicit script/command invocations are preserved, and execution policy is respected. Original MIT Bash/Zsh adapters use PS0/PROMPT_COMMAND and native Zsh hooks, respectively. Recognized interactive launches load adapters after the requested startup files; explicit scripts and unsupported modes are unchanged. Bash tracking avoids history and DEBUG traps; Zsh command metadata is bounded at a UTF-8 boundary. Publish and activation remove obsolete GPL helper assets from older output folders. See Integration/posix/README.md for bootstrap semantics and limits.

Directory metadata is parsed separately from the Windows process working directory. Each shell receives a random `TOIQTTY_CWD_TOKEN` (forwarded into WSL through `WSLENV`), and the PowerShell, Bash and Zsh adapters append it to OSC 7. For integrated shells only a matching token makes a location local; OSC 7 from programs inside the shell, such as ssh, stays display-only like a remote authority. Shells without integration keep unauthenticated tracking. Local Windows URIs decode percent escapes; Kitty cwd URIs preserve literal paths. Local WSL drive mounts map to Windows drives and Linux paths map through the selected distro's filesystem. Other authorities remain display-only and are not probed by local Git. Session persistence and split/new-workspace launch use the Windows working directory rather than remote display text. Only changed cwd metadata is parsed.

Ghostty's notification callbacks feed both bounded Activity history and a Windows App SDK notification adapter. Foreground focused terminals stay silent; other terminals can deliver native toasts when enabled in Settings. Delivery is limited to one toast per two seconds, while Activity retains notices. Builder APIs escape terminal text. Activation targets workspace and pane IDs, restores a minimized window, and supports current-user instance forwarding. Registration precedes activation handling and is released on exit; isolated notification tests also remove their registration/history. `copy-sdk-resources.ps1` extracts the missing Insights resource DLL from the pinned SDK MSIX for self-contained build/publish output. OS notification settings and elevated-process restrictions still apply.

## Installation and rollback

Portable releases include a schema-1 file manifest with normalized paths, sizes and SHA-256 hashes. Installation rejects missing, changed and unlisted runtime files and checks the executable version. Each release is staged, verified again and moved to an immutable `versions/<version>` directory. An exclusive installation lease serializes pointer changes. Activation atomically replaces each pointer file and restores the prior shortcut/state if either operation fails; this is failure recovery, not an atomic transaction across a power loss.

Local ZIP updates require an expected SHA-256 digest, prevalidate paths, Windows case duplicates, symlink entries and expansion limits, then use the same installer. Rollback verifies the previous payload before activation. Legacy versioned installs receive an external hash snapshot without writing into their live runtime directory. Running hosts and frontends are never terminated by these tools. Hashes provide integrity checks, not publisher authentication; publisher authentication is optional and separate.

## Validation boundaries

Core/Client checks exercise the referenced production assemblies, native terminal bridge, real ConPTY shells and isolated session hosts. WinUI diagnostics exercise the real renderer, controls, input ordering and resource lifetimes. Native lifetime checks support AddressSanitizer; DirectX diagnostics support the debug layer and offscreen readback. Browser and WSL adapter suites remain separate entry points. See [README.md](README.md#verify) for commands.

Automated device replacement, DPI changes and composition handlers do not substitute for physical driver loss, monitor transitions, native IME candidate input, Narrator or real sleep/wake. Performance runs report submission timing separately from displayed refreshes. Historical test reports belong in ignored artifacts rather than the description of current architecture.
