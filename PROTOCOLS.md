# Terminal protocol compatibility

Ghostty protocol compatibility is a core toiqtty milestone. Using the VT parser is necessary, but the host must also preserve its output, expose its state, render it correctly, and implement its platform callbacks. A parser recognizing a sequence does not by itself establish application support.

This matrix describes version 0.2.0 and the Ghostty revision in `native/ghostty.lock.json`. It is a coverage record, not an exhaustive conformance certificate. Follow [Ghostty's VT reference](https://ghostty.org/docs/vt/reference) and [Kitty's graphics specification](https://sw.kovidgoyal.net/kitty/graphics-protocol/) when extending coverage. toiqtty integrates protocols already implemented by the pinned upstream engine; it does not independently implement missing upstream protocols.

Shared-memory transfer remains unavailable: upstream returns UnsupportedMedium on Windows. WSL clients should continue using direct transfer. Longer production workloads remain useful. |
| Kitty Unicode placeholders | Ghostty resolves fragments and inherited placeholder coordinates; placeholder glyphs are suppressed. Relative placements can resolve virtual parents. Real Kitty/tmux passthrough and resize checks pass. | Broader combinations of placeholder inheritance and parent chains. |

| OSC 8 hyperlinks | Ghostty resolves viewport link targets; Ctrl+click opens HTTP(S) and mail links; hover cursor and target tooltip. | Configurable URI handling. |

## Implementation boundaries

Version 0.2.0 moves live terminals into an independent current-user session host. Sidebar sessions contain tabs with independent split trees. Closing or crashing the WinUI process preserves child PIDs, in-memory shell variables, terminal history and Ghostty images; reconnect restores the active tab and focused pane. Private IPC carries lossless cells/placements and generation-cached image pixels. Hidden engine state continues processing output and animation clocks. The host exits after the last live shell ends. This changes ownership and transport only; no upstream protocols or native patches were added. The opt-in `-Sessions` suite checks host lifecycle and separate-process WinUI close/crash recovery.

Version 0.1.9 fixes Japanese IME mode keys being consumed as shortcuts and stale preedit being sent during cancellation. Native Microsoft Japanese IME candidate selection, exact `日本語` commit and empty `春` cancellation were verified against the packaged build. Actual GPU device loss remains unverified.

On 2026-10-14, an exact copy of release 0.5.8 passed 57 physical DPI checks across 100% → 175% → 100% scaling. The run checked unified title-bar control regions, terminal cell alignment, caret positioning, retained image pixels, prompt joins, external UIA geometry and the same shell throughout. The test window exited normally, all 585 copied application files matched the release, and the existing user frontend/session host remained running. Evidence: `artifacts/dpi-validation-0.5.8.json` and `artifacts/dpi-check-0782e6c0dcac48a3a30beacd59508c70/dpi-smoke.json`. Native IME candidate placement during monitor transitions and physical GPU device loss remain separate checks.

On 2026-10-13, the 0.5.2 diagnostic build passed 36 checks while moving its own isolated window across real monitors at 100% (96 DPI) and 175% (168 DPI), then returning to 100%. `scripts/test-dpi.ps1` checks Windows/XAML/Win2D DPI agreement, integral physical cell dimensions, input caret anchoring, retained Kitty image pixels, seam-free colored prompt joins, Unicode text, external UIA text bounds and point-to-character mapping, and preservation of the same shell. The external UIA reader opts into per-monitor DPI awareness to avoid virtualized screen coordinates. The run does not override rendering DPI, inject desktop input or change display settings. It does not establish native IME candidate positioning or physical mouse input. Reports and screenshots are under `artifacts/dpi-check-*`; the recorded successful run is `artifacts/dpi-check-df238093e54b479bb795065642dfffa9/dpi-smoke.json`.

Version 0.1.8 adds a guided physical-validation driver and corrects cold notification startup by retrieving the SDK's initial payload through App Lifecycle after registration. The published regression gate passes 262 terminal/interop, 66 WinUI and two additional real Windows COM notification activation checks (330 total). Five manual checks are reported Pass: Narrator, external file copy, toast interaction, sleep/wake and graphics-reset shortcut recovery. Windows System events corroborate the real sleep/wake cycle, and the disposable Unicode file's quoted path reaches the literal receiver while the source remains present. Native IME candidate validation remains Blocked after clarification that input was typed/pasted normally; mixed-monitor DPI is Blocked with one display. No real driver timeout/device-removal event was observed. The physical session used the 0.1.7 diagnostic build; the cold-activation fix is validated separately in 0.1.8. Reports are `artifacts/validation-0.1.8.json` and `artifacts/hardware-validation-0.1.8.json`. Missing upstream protocols remain deferred.

`native/patches/graphics-host.patch` adds host hooks to the pinned Ghostty source for its existing animation clock and Unicode-placeholder fragment iterator. It also applies Ghostty's renderer origin rule to relative placements with virtual parents. `native/patches/dnd-host.patch` exposes upstream Kitty DnD state, conclusion callbacks and source operation masks, and emits replies through the existing PTY callback. Host cancellation delegates to the upstream conclusion path. Protocol parsing, image composition, placement and DnD state are not reimplemented in C#; the OSC 66 parser and terminal screen implementation are unchanged.

Image storage is limited to 64 MiB per screen. Native immutable snapshots, managed pixel copies, and GPU textures consume additional memory. Caches use Ghostty generations, deduplicate shared image placements, and release entries absent from the visible snapshot. Background workspaces retain terminal state; their views and GPU textures can be recreated independently.

Microsoft's ConPTY redistributable is pinned in both projects and shipped with its adjacent `OpenConsole.exe`. Tests cover real child output so a passing parser-only test cannot hide transport loss. The system ConPTY on the development machine stripped Kitty APC before Ghostty received it.

## Release gate

The 0.8.0 candidate passed 60 checks while moving its isolated window across actual 100% → 175% → 100% displays on 2026-10-19. The native renderer retained image pixels, colored prompt joins, integral cell dimensions, caret anchoring, Unicode, external UIA screen-point mapping and the same shell across the transitions. Evidence: `artifacts/dpi-check-db598cda7fe84129bb9c75b99cc935a2/dpi-smoke.json` and `artifacts/directx-overnight-20261019/final-physical-dpi.log`. These were real display moves without changing display settings or injecting desktop input. Physical IME candidate placement and actual driver removal remain separate checks.

Version 0.9.0 changes terminal drawing to the dedicated native Direct3D 12 renderer. DirectWrite shaping, Ghostty parsing/state, Kitty placement snapshots and host protocol 2 remain unchanged. Native GPU checks compare text at five rendering DPIs, color emoji, combining marks, Powerline joins, nested clips, premultiplied alpha and cropped images. Stress checks read actual D3D backbuffers while replacing owned hardware/WARP devices and resizing native presentation resources. These are application device transitions, not physical driver removal. Onscreen marker checks record display-power skips explicitly; a powered-off monitor cannot establish onscreen composition correctness. The original Win2D pixel reference remains diagnostic only.

Version 0.7.0's optional `pane-output-watch` and `navigation-save` capabilities extend the protocol-2 session IPC only. They add no terminal escape sequences or independently implemented terminal protocols. Retained layouts and DirectWrite metric-buffer reuse preserve the existing Ghostty parser and renderer inputs. Automated recovery checks inject the application's device-loss callback and synthetic power notifications; actual driver reset and system sleep remain separate physical validation.

Version 0.7.1 additionally negotiates `metadata-batch` and `resize-clears-selection` for session bookkeeping. Older protocol-2 hosts retain their existing paths. Managed/native buffer reuse and immutable status caches do not change the cell wire format or add terminal protocols. The seeded snapshot differential fixture compares incremental captures and full/delta transport against full Ghostty captures, including Unicode, selection, scrolling, resize, reset, static graphics and rejected-payload isolation.

Version 0.7.3 supersedes the initial metadata batching capability with `metadata-batch-v2`, adding explicit response-overflow reporting and read-only subdivision at the existing 16 MiB message limit. Older peers retain individual state polling. This is session IPC only; it adds no terminal escape sequences, never replays shell input, and does not truncate upstream command/status events.

Version 0.7.6 preflights outgoing snapshot bytes at the existing 96 MiB limit without changing their wire format. The optional real Kitty/tmux fixture enables both tmux passthrough and its RGB terminal feature: quantizing placeholder foreground colors into palette indices loses the image ID encoded in those colors. Its startup marker uses split `printf` arguments so command echo cannot satisfy readiness. These are test configuration and validation changes; image parsing and placeholder geometry remain upstream implementations.

Keep the host-protocol gaps above in the compatibility milestone. Before claiming Ghostty protocol parity, implement the applicable missing callbacks and renderer state, then exercise capability negotiation, fragmented streams, reset/resize/screen-switch lifetimes, and real applications. The current automated checks cover representative behavior; they do not substitute for that application matrix.

## Hardening and client matrix

Version 0.1.4 adds incremental native row extraction, retained GPU text/background layers, bounded shaped-layout caches, an 8 MiB / 256-entry ordered input queue, nonblocking render capture, validated atomic session writes, and a per-data-directory instance lease with activation forwarding. UI Automation exposes immutable viewport text ranges; it does not expose the whole scrollback as one document.

The suite includes real Neovim and fzf when installed, four concurrent sustained-output shells and optional WSL/Kitty 0.49.2/tmux 3.8 checks via `scripts/test-interop.ps1`. Tools are checksum-verified and built in `.tools`, never installed globally. The tested WSL console path requires `icat --use-window-size` because automatic pixel-size detection fails. WSL clients explicitly use direct streaming: Linux file paths and POSIX shared-memory names are not local Windows transfer handles.

Version 0.1.5 adds a separate-process UIA client, synchronous selection readback, focusable terminal documents, composition commit/cancel checks, power-notification handling, CanvasDevice replacement and live Win2D DPI changes. CreateResources invalidates the captured version as well as device resources, so an idle shell's graphics reappear after recovery. Font measurement outside Draw reports actual device-loss exceptions to CanvasControl.

The ten-minute soak processed 13,094,864 bytes from four real shells with 76,277 successful snapshots and 19,095 fragmented 256×256 image replacements. Snapshot p95 was 0.3593 ms; private-memory growth after warmup was 4,160,171 bytes. The published two-minute renderer soak presented 1,484 frames, kept 16 live textures and at most 1,300 shaped layouts, and showed no private-memory growth after warmup. Reports are `artifacts/soak.json`, `artifacts/renderer-soak-0.1.5.json` and `artifacts/validation-0.1.5.json`. The published regression run passes 175 terminal/interop and 57 WinUI checks; its external UIA client performs 40 additional subchecks within the UIA integration check.

These checks do not establish physical IME input, Narrator speech/navigation, a real mixed-monitor transition, an actual driver reset, or system sleep/wake. At the time of that soak, this machine exposed one display at 175% scaling; the later physical mixed-monitor result is recorded above. The power test sends messages only to the isolated test window; the device test switches that window between hardware and WARP rendering. Neither resets system graphics nor puts the computer to sleep.

Version 0.1.6 passes 207 terminal/interop and 60 WinUI checks, including the WSL/Kitty/tmux matrix. Added coverage exercises file/temp capability queries, exact offsets/lengths, Unicode file paths, Windows path rejection, guarded temp consumption, reset/alternate-screen configuration, real PowerShell/ConPTY file transfers and rendered file/temp image pixels. DnD checks exercise Copy/Move conclusion, cancellation, reset, unregister, replacement, disposal, a real ConPTY client's Move completion and an unresponsive client's timeout. WinUI MIME capture checks text, HTML, RTF and the aggregate byte limit. Reports are `artifacts/validation-0.1.6.json`, `artifacts/published-validation-0.1.6.log` and the referenced UI report directory. The 0.1.5 soak reports remain prior-version evidence; long soaks were not rerun for 0.1.6. Physical external-app drag/drop testing remains.

Version 0.1.7 passes 262 terminal/interop and 66 WinUI checks against the published application, including the optional WSL/Kitty/tmux and extracted zsh matrix. New checks exercise PowerShell 7 and 5.1 command boundaries, Unicode and bounded long-command metadata, native/cmdlet exit codes, duration, custom prompt status, strict-mode startup, shell EOF, missing completion markers, default WSL shell discovery, inherited Linux cwd, upstream bash/zsh hooks, preserved ZDOTDIR, directory authority handling and notification instance forwarding.
